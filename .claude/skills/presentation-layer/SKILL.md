# Presentation layer (`src/routes`, `src/ui`)

## What belongs here

- `src/routes/`: one screen per file (`Landing`, `CreateRoom`, `JoinName`, `RoomGate`, `Rate`, `Waiting`, `Results`) and `RoomContext.ts`.
- `src/ui/`: reusable parts (`Screen`, `PillButton`, `ScorePicker`, `ProgressSegments`, `ParticipantList`, `ConfirmDialog`, `ShareCard`, `RankingList`, `EntryDetail`, `OfflineBanner`, `tints`, `useDebounced`).

## Boundary rules

- Import logic from `domain` and data functions from `firebase/rooms`. Never import `firebase/*` SDK modules here.
- Room screens get state from `useRoomContext()`, which `RoomGate` provides. Do not subscribe again inside a screen.
- `ui` components that need room data also use `useRoomContext()` (`ParticipantList`, `ShareCard`).
- Logic that has no UI (averages, ranks, progress) goes to `domain`, with a unit test.

## Add

- Screen: follow the `screen` skill.
- Component: put it in `src/ui/`, build it from react-aria-components, add a `*.test.tsx`.

## Edit

1. Search the accessible names you change in `src/**/*.test.tsx` and `tests/e2e/flow.spec.ts`.
2. Keep `Screen` props (`title`, `subtitle`, `onBack`, `actions`, `footer`) as the layout API.
3. Run `pnpm test`, and `pnpm test:e2e` when the flow changes.
