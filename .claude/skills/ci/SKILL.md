# CI and deploy for Tastebench

## Workflows on main

- `.github/workflows/deploy.yml` ("Deploy to GitHub Pages"), on push to `main`:
  1. `actions/checkout@v4`, `pnpm/action-setup` pinned to SHA `fc06bc1…` (v4.4.0), `actions/setup-node@v4` with `node-version-file: .tool-versions` and `cache: pnpm`.
  2. `pnpm install --frozen-lockfile`, then `pnpm test`.
  3. "Check Firebase config" fails when `vars.VITE_FIREBASE_API_KEY` or `vars.VITE_FIREBASE_PROJECT_ID` is empty.
  4. `pnpm build` with the six `VITE_FIREBASE_*` variables, `actions/upload-pages-artifact@v3` with `dist`, `actions/deploy-pages@v4`.

## Workflows in PR #1 (not on main yet)

- `build.yml` (job `unit-tests`): `pnpm test` on pull requests and pushes to `main`. A ruleset on `main` can require the `unit-tests` check.
- `emulator-tests.yml`: manual; Java 21 and `pnpm test:emu`.
- `deploy-rules.yml`: manual and on push to `main` that changes `firestore.rules`, `firebase.json` or the workflow; needs the `FIREBASE_SERVICE_ACCOUNT` secret.

## Reproduce CI locally

1. Run `pnpm install --frozen-lockfile`.
2. Run `pnpm test`.
3. Run `pnpm build`.
4. `.claude/pre-pr-checks` runs `pnpm test` and `pnpm exec tsc -b`, and blocks `gh pr create` on failure.

## Debug a failed run

1. `gh run list --limit 5`, then `gh run view <id> --log-failed`.
2. "Check Firebase config" failing means the repository variables are missing or were added after the run started. Rerun with `gh run rerun <id>`.
3. "No artifacts named github-pages" at `deploy-pages` means Pages is not enabled. Set Settings, Pages, Source to "GitHub Actions" and rerun.

## Change a workflow

- Pin each third-party action (not `actions/*`) to a full commit SHA with a version comment.
- Reuse the setup steps above so local and CI use the same Node and pnpm.
- Keep `permissions` minimal per workflow. Repository secrets reach every branch through `workflow_dispatch`; use a GitHub Environment limited to `main` for deploy keys.

## Ship a change

Branch, PR into `main`, merge. The merge deploys the site. If the PR changes `firestore.rules`, deploy the rules too (see the `firestore` skill). The user pushes and opens PRs, because `gh-organization-check` blocks agent writes to this GitHub org.
