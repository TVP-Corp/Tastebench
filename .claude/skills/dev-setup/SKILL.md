# Set up Tastebench from zero

## Toolchain

1. Install Node `24.14.0` (`.tool-versions`; asdf reads it).
2. Enable pnpm through Corepack, or install pnpm `11.21.0`. `package.json` `packageManager` pins it with a hash.
3. Install Java 21 or later. The Firestore emulator needs it.
4. Run `pnpm install`. pnpm runs no dependency build scripts unless `pnpm-workspace.yaml` `allowBuilds` allows them; the listed ones (`@firebase/util`, `protobufjs`, `re2`) are set to `false`.
5. For e2e, run `pnpm exec playwright install chromium`.

## Check the setup

1. Run `pnpm test`. All unit tests must pass.
2. Run `pnpm test:emu`. It downloads the emulator jars on the first run.

## Environment

- `.env.example` lists `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`, `VITE_USE_EMULATOR`.
- Local work needs only `VITE_USE_EMULATOR=true`. Real values come from the Firebase console (Project settings, Your apps, web app config). Put them in `.env.local`, never in a committed file.

## New Firebase project (one time)

1. Create a project on the Spark plan. Do not add billing.
2. Enable Authentication, Sign-in method, Anonymous.
3. Add the Pages host (`tvp-corp.github.io`) under Authentication, Settings, Authorized domains.
4. Deploy the rules: `pnpm exec firebase login`, then `pnpm exec firebase deploy --only firestore:rules --project <project-id>`. This creates the `(default)` database if it is missing.

## GitHub repo (one time)

1. Add the `VITE_FIREBASE_*` repository variables under Settings, Secrets and variables, Actions, Variables.
2. Set Settings, Pages, Source to "GitHub Actions". The repo must be public on the free plan.
3. For the rules workflow (PR #1), add the `FIREBASE_SERVICE_ACCOUNT` secret: a JSON key of a service account with Firebase Rules Admin, Service Usage Consumer and Cloud Datastore Viewer.
