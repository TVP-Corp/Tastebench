# Playwright in Tastebench

- One spec: `tests/e2e/flow.spec.ts`, "three people rate, close, rename and lock a room". It opens 3 browser contexts (creator and two raters) at 390x844.
- Config: `playwright.config.ts`. Chromium only, `workers: 1`, `timeout: 90_000`. `webServer` starts `npx vite --port 5199 --strictPort` with `VITE_USE_EMULATOR=true` and waits up to 120 s.

## Run

1. Run `pnpm exec playwright install chromium` once.
2. Run `pnpm test:e2e`. It wraps Playwright in `firebase emulators:exec`, so the emulators start and stop with the run.
3. On failure, read `test-results/<test>/error-context.md`. The `[WebServer]` lines show the browser console, which is where React errors appear.

## Add or change a step

- Use the helpers at the top of the spec (`join`, `joinWithCode`, `joinByLink`, `pick`) before you write new locators.
- Select by role and accessible name: `getByRole('button', { name: 'Create room' })`, `getByLabel('Entry 1', { exact: true })`.
- Assert visible outcomes with `await expect(...).toBeVisible()`; do not sleep.
- Keep it one critical-path flow. Edge cases belong in component tests or `tests/emu`.

## Gotchas

- Renaming a button label breaks the spec. Search `tests/e2e/` when you rename.
- The e2e test catches runtime errors that jsdom misses (for example a Promise returned from an effect). Run it after changes to effects or navigation.
