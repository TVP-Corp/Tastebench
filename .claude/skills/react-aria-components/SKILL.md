# react-aria-components in Tastebench

Every interactive control comes from `react-aria-components`. It gives keyboard, focus and screen-reader behavior for free, and the tests query by role.

## Controls in use

- `Button` with `onPress` (never `onClick`). Icon-only buttons get `aria-label` (`"Participants"`, `"Back"`, `"Edit title of <title>"`).
- `TextField` + `Label` + `Input`/`TextArea`. A hidden label uses `className="sr-only"` (`CreateRoom.tsx` list fields). `FieldError` shows validation (`Landing.tsx`).
- `ToggleButtonGroup` + `ToggleButton` with `selectionMode="single"` and `disallowEmptySelection` for the score picker (`src/ui/ScorePicker.tsx`). The group passes a `Set<Key>` to `onSelectionChange`; ignore an empty set.
- `ModalOverlay` + `Modal` + `Dialog` + `Heading slot="title"` for sheets and dialogs. Destructive confirmations use `src/ui/ConfirmDialog.tsx` (`role="alertdialog"`).
- `Tabs`, `TabList`, `Tab`, `TabPanel` for the ranking tabs in `Results.tsx`.

## Add a control

1. Pick the react-aria component that matches the role. Give it a visible label or `aria-label`.
2. Style states with `data-[selected]`, `data-[pressed]`, `data-[disabled]`, `data-[focus-visible]` (see the `tailwind` skill).
3. In the test, query with `getByRole('button', { name })`, `getByRole('radio', { name })`, `getByRole('alertdialog')`. Use `fireEvent.click` or `userEvent.click`.

## Edit a control

- Keep the accessible name stable. Tests and `tests/e2e/flow.spec.ts` select by name (for example `'Close room and show results'`, `'.3'`, `'Skip'`).
- If you rename a label, search for it in `src/**/*.test.tsx` and `tests/e2e/`.

## Gotchas

- `ToggleButton` inside a group renders `role="radio"`; a standalone `ToggleButton` renders a button with `aria-pressed`.
- `isDisabled` on the group disables every child; per-button `isDisabled` handles the "10 allows only .0" rule.
- Do not emit `onChange` when the value does not change; the picker checks `next !== value`.

## Hard rules

- **A11Y-KEYBOARD**: Do not ship an interactive control that a keyboard cannot reach or operate. Instead, use a native control or a react-aria-components control (`Button`, `ToggleButton`, `TextField`), or add focusability and key handlers that match its role.
