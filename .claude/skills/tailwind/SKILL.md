# Tailwind CSS v4 in Tastebench

- Tailwind v4 runs through the `@tailwindcss/vite` plugin in `vite.config.ts`. There is no `tailwind.config.js`. `src/index.css` imports Tailwind.
- Write utility classes inline in `className`. Shared class strings live as constants next to the component (`base`, `cls`, `skipCls` in `src/ui/ScorePicker.tsx`; `btn` in `src/ui/ShareCard.tsx`).
- Style react-aria-components states with data attributes: `data-[selected]:`, `data-[pressed]:`, `data-[disabled]:`, `data-[focus-visible]:ring-2`. Do not use `:hover`-only states; the app is touch-first.
- Mobile first: screens are centered with `max-w-[480px]` in `src/ui/Screen.tsx`, height `min-h-dvh`, background gradient `from-rose-50 via-sky-50 to-violet-50`.
- Touch targets: interactive elements use `min-h-11` or `min-h-12` and `min-w-11`.
- Entry cards use the pastel tints in `src/ui/tints.ts`, picked by index (`TINTS[index % TINTS.length]`).

## Add a style variant

1. Do not pass a class that conflicts with a base class (for example `bg-white` over `bg-black`). Which one wins depends on the generated CSS order, not on the class order.
2. Add a named variant to the component instead. Example: `PillButton` has `variant: 'primary' | 'secondary'` with a `VARIANTS` map (PR #1).

## Edit a style

- Change the constant or the component, not each call site.
- Check the screen at 390x844, the viewport that the e2e test uses.
- Keep the Skip toggle tint light (`bg-red-50`, `border-red-200`): it must read as an option to avoid, not as an error.
