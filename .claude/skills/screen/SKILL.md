# Add or change a screen

## Add

1. Create `src/routes/<Name>.tsx` with a default export. Build it from `Screen` (`src/ui/Screen.tsx`): pass `title`, `subtitle`, `onBack`, `actions` (icon buttons) and `footer` (primary actions).
2. Inside a room, read state with `const { room, me, isCreator, code, uid } = useRoomContext()` and return `null` while `room` is missing.
3. Register the route: room screens in `RoomGate.tsx` `Routes`, top-level screens in `App.tsx`. Update the gate `target` logic if the screen depends on status (see `react-router`).
4. Primary actions use `PillButton` (`variant="secondary"` for the second action in a row). Sheets use `ModalOverlay`/`Modal`/`Dialog`; confirmations use `ConfirmDialog`.
5. Add `src/routes/<Name>.test.tsx`: mock `../firebase/app` and `../firebase/rooms`, render with `RoomContext.Provider` and `MemoryRouter`, assert by role.
6. Run `pnpm test` and check it at 390x844 with `VITE_USE_EMULATOR=true pnpm dev`.

## Edit

- Changing a label or button name: search `src/**/*.test.tsx` and `tests/e2e/flow.spec.ts` for it.
- Moving between entries: `RateEntry` is keyed by index, so per-entry state resets on its own. Flush pending debounced notes (`saveNote.flush()`) before you navigate.
- Showing a control only to the creator: gate on `isCreator` and on `room.status` (never after `locked`).
- Run `pnpm test:e2e` when the change touches the create, join, close, rename or lock flow.
