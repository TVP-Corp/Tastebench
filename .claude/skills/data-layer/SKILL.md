# Data layer (`src/firebase`)

## What belongs here

All Firebase SDK calls. Nothing else in the app imports `firebase/*`.

- `app.ts`: `initializeApp`, `auth`, `db`, the emulator switch.
- `rooms.ts`: `createRoom`, `joinRoom`, `setScore`, `setNote`, `removeParticipant`, `closeRoom`, `renameEntry`, `lockRoom`, `roomExists`, `subscribeRoom`, `subscribeParticipants` (and `discardRoom` after PR #1).
- `useAuth.ts`: anonymous sign-in once per page, returns the uid or `null`.
- `useRoom.ts`: subscribes to the room and its participants only when both `uid` and `code` are set (deps `[code, uid]`), and returns `{ room, participants, me, isCreator, error }`.

## Boundary rules

- Depends on `domain` only (types, `isValidScore`, `generateCode`, `newId`).
- `routes` and `ui` call these functions; they never touch `db` directly.
- Every new write needs a rule branch in `firestore.rules`.

## Add a write

1. Add `export async function <name>(code, ...)` in `rooms.ts`. Validate inputs from the domain (see `setScore`).
2. Use a field-path `updateDoc` for one field, `writeBatch` for several documents.
3. Add the rule and tests (see the `firestore` and `room-action` skills).
4. Callers do `<name>(...).catch((e) => console.error(...))` without `await`.

## Edit a subscription or mapping

- Keep defaults for missing fields (`d.scores ?? {}`), so old documents load.
- Pass `onError` through; `useRoom` turns it into `error`, which `RoomGate` shows with "Try again".
- `src/firebase/useRoom.test.tsx` covers the hook with mocks; `tests/emu/rooms.test.ts` covers the functions on the emulator.
