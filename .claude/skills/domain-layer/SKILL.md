# Domain layer (`src/domain`)

## What belongs here

Pure TypeScript with no React, no Firebase, no browser API. Input in, output out.

- `types.ts`: `Score`, `Item`, `Room`, `Participant`, `RankedEntry`, `ResultsSnapshot`.
- `score.ts`: `MAX_WHOLE = 10`, `MAX_TENTHS`, `splitTenths`, `pickWhole`, `pickDecimal`, `formatTenths`, `formatAverage`, `isValidScore`.
- `results.ts`: `computeResults(entries, criteria, participants)`, `rankEntries`.
- `progress.ts`: `entryState`, `participantProgress`, `firstIncompleteIndex`.
- `code.ts`: `CODE_ALPHABET`, `generateCode`, `normalizeCode`, `isValidCode`, `newId`.

## Boundary rules

- `domain` imports only from `domain`.
- `firebase`, `routes` and `ui` import from `domain`. Never the reverse.
- A type change here ripples to `src/firebase/rooms.ts` (mapping and writes) and to `firestore.rules`.

## Add

1. Write the test first in the matching `*.test.ts` (Vitest, plain values; `src/test/fixture.ts` has shared people).
2. Add the function and export it.
3. Run `pnpm test src/domain`.

## Edit

1. Find callers with the `LSP` tool `findReferences` (or `impact_analyze`).
2. Update the tests for the changed behavior first, then the code.
3. If `types.ts` changes, follow the `room-action` skill for the data and rules side.
