# react-router in Tastebench

- The app uses `HashRouter` (`src/App.tsx`), because GitHub Pages serves static files and has no SPA fallback. URLs look like `https://<host>/Tastebench/#/r/ABC234/rate/0`. Vite `base: './'` keeps assets relative.
- Top-level routes: `/` (`Landing`), `/create` (`CreateRoom`), `/r/:code/*` (`RoomGate`).
- Room routes, inside `RoomGate`: `rate/:index`, `wait`, `results`.

## How RoomGate decides the screen

1. `decideView({ room, me, wasMember, isCreator, hadRoom })` in `src/routes/RoomGate.tsx` returns `loading`, `not-found`, `removed`, `join`, `rate`, `wait` or `results` (`discarded` after PR #1).
2. A `target` sub-path is computed from the status and the current sub-path, and a `useEffect` navigates there with `replace: true`.
3. The first move from `open` to `preview` (`justClosed`) sends everyone to `results` once. After that, `rate/` stays reachable in preview so people can edit.
4. `locked` always forces `results`.

## Add a room screen

1. Add `<Route path="<name>" element={<Name />} />` in the `Routes` of `RoomGate`.
2. Decide in the `target` logic when the gate allows or forces the new path. Add a `decideView` case only for a new state.
3. Add cases to `src/routes/RoomGate.test.tsx`: it mocks `useRoom` through `state.value` and renders with `MemoryRouter`.

## Edit navigation

- Navigate with absolute paths: `navigate(`/r/${code}/rate/${i}`)`.
- `Rate` keys `RateEntry` by index, so each entry change remounts it. Use that for per-entry reset (scroll to top, note state).
- Use `replace: true` for redirects the gate makes, so Back does not bounce.
